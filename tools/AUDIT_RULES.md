# 정보처리산업기사 퀴즈 프로그램 — 원본 대조 수정 마스터 규칙 (v1, 2026_1 파일럿 기준)

## 0. 결론
2026_1 회차(60문항)를 원본 PDF와 100% 동일하게 만드는 과정에서 발견된 오류 유형은 **총 11가지**.
같은 패턴이 나머지 12회차(2022_1~2025_3, 60문항×12=720문항)에도 반복될 확률이 매우 높음.
아래 규칙을 그대로 프롬프트로 던지면 "발견→수정→재발견→재수정" 반복 없이 **1패스**로 끝남.

---
## 1. 절대 규칙 (위반 금지)
| # | 규칙 |
|---|---|
| 1 | "완료됐다" 보고 전 반드시 **라이브 화면 캡처 또는 DOM 직접 확인**으로 검증. 자동 대조 스크립트 결과만 믿고 보고 금지 (실제로 스크립트가 문구 차이로 오탐낸 사례 있었음) |
| 2 | 대조 기준은 **60문항×13회차 원본 PDF** — 문제/선택지/정답/해설 그림까지 전수 |
| 3 | 한 화면에 여러 유형(예: 그래프 선택지 + 트리 순회)이 같이 있으면, 처리 중인 유형만 고치고 넘어가지 말 것. 같은 화면 인접 문제까지 함께 확인 (id 557 트리 순회 누락 사례 있었음) |
| 4 | "그림/표/다이어그램" 단어가 있다고 무조건 시각화 대상 아님. 그림 없이 풀리는 순수 지식형 문제는 텍스트 유지, 그림이 실제 풀이에 필요한 문제만 시각화 |
| 5 | 원본 그림을 이미지로 그대로 못 넣는 구조적 제약이 있는 한, 그림이 전달하는 **구조 정보**를 SVG나 텍스트로 빠짐없이 옮길 것. "그림 참고"로 퉁치기 금지 |
| 6 | 실전 모드 문제 순서는 항상 **과목 우선 정렬**(1과목 20→2과목 20→3과목 20). DB id 정렬 절대 금지 |

## 2. 문제 유형별 체크리스트
| # | 유형 | 증상 | 해결 | 검증 방법 |
|---|---|---|---|---|
| 1 | 코드블록 (C/Java/HTML/JS) | 코드가 한 줄로 뭉쳐 들여쓰기·줄바꿈 소실 | 마크다운 코드펜스(```)로 감싸서 원본 형태 보존 | 라이브 화면에서 들여쓰기 육안 확인 |
| 2 | 그래프형 4지선다 (인접행렬 등) | 선택지 4개가 서로 다른 그래프인데 텍스트/그림 1개로 뭉뚱그림 | 선택지 4개 각각 독립 SVG로 렌더링, ①②③④ 라벨 | 자기루프 포함 여부·화살표 방향까지 원본과 구조 일치 확인 |
| 3 | 자기루프(self-loop) | 노드에서 동떨어진 원으로 그려짐, 좌표 음수 시 패널 밖으로 삐져나감 | 노드에 붙어 돌아나오는 화살표 형태로, 좌표 양수 강제, 클리핑 방지 | SVG DOM circle/line 좌표 직접 확인 |
| 4 | 트리/그리드 구조 | 텍스트 설명만 있어 시험지처럼 안 보임 | 순수 Python SVG 렌더러로 직접 그림 (Graphviz 미사용 — Streamlit Cloud 배포 호환 필수) | 노드 라벨·선 위치가 원본과 일치하는지 DOM 좌표 확인 |
| 5 | 박스형/글머리 문제 | 디스크 큐, 추상클래스 빈칸, 관계 설명 등이 뭉쳐서 표시 | 원본처럼 구분된 레이아웃으로 정리 | 시각적 대조 |
| 6 | HTML 표 렌더링 순서 | tfoot 등 소스 순서≠실제 렌더링 순서 → 학습자 혼란 | 정답 스포일 없이 "렌더링 순서"만 보여주는 보조 그림 추가 | 실제 브라우저 렌더링 순서와 보조 그림 일치 확인 |
| 7 | 실전 모드 문제 순서 | 신규 문항 추가 시 DB id 정렬로 과목 순서 깨짐 | 과목 우선 정렬 로직 고정 | 20/20/20 순서 라이브 확인 |
| 8 | 잘린/누락 선택지 | 외부변수 등 선택지 일부가 잘려서 저장됨 | 동일 문제가 다른 회차에 온전히 있으면 그걸로 복구, 없으면 PDF 재확인 | 원본 대조 |
| 9 | 특수 결과표 (SQL GROUP BY 등) | 표 형태 계산 결과 누락/오기 | 원본 표 값 그대로 반영 | 값 단위 대조 |
| 10 | PDF 한글 인코딩 깨짐 | 텍스트 추출 시 한글만 빈칸(숫자는 정상) | **poppler로 이미지 렌더링 후 육안 확인**을 기본으로, 텍스트 추출은 보조용만 | 이미지 렌더링본과 텍스트 대조 |
| 11 | "그림 필요 여부" 오판 | 키워드만 보고 전부 고치거나 전부 스킵 | 문항별로 "그림 없이 풀리는가?" 직접 판정 후 분류 | 전수 키워드 검색 → 1건씩 판정 근거 기록 |
| 12 | 뒤늦게 복구된 문항의 순서 붕괴 | 나중에 높은 id로 추가/복구된 문항이 (subject, id) 정렬 때문에 과목 블록 맨 끝으로 밀려남 (예: 28번 문제가 40번 자리에 표시) | `qnum` 컬럼에 원본 문제 번호(raw_cbt의 num)를 채워 넣고, `pick_cbt_round_pool`이 qnum 있는 문항은 그 위치에 끼워 넣도록 정렬 | 라이브에서 `[N/60]` 표시가 원본 PDF의 실제 문제 번호와 일치하는지 확인 |
| 13 | 중복 문항 prefix 충돌 | "다음 C언어 프로그램이 실행되었을 때의 결과는?" 같은 흔한 문두를 공유하는 서로 다른 문항이 자동 qnum 매칭에서 서로 뒤바뀌거나 매칭 실패 | 실제 코드/보기 내용으로 원본 PDF 해당 페이지와 1:1 대조해서 수동으로 qnum 배정 | PDF 해당 번호 문제의 코드/보기와 CSV choice 값이 정확히 일치하는지 확인 |
| 14 | 표/데이터가 한 줄로 뭉개짐 | "학번(SNO)이름(SNAME)..." 처럼 컬럼 헤더와 각 행 값이 공백 없이 이어붙음 | 마크다운 테이블(`|---|---|`)로 재구성 | 라이브에서 실제 표 형태(행/열 구분)로 렌더링되는지 확인 |
| 15 | 서브스크립트/표기 위치 이동 | "1010(2)"처럼 숫자 뒤에 붙어야 할 진법 표기가 문장 끝으로 밀려남 (PDF 추출 시 위치 정보 소실) | 원본 이미지에서 정확한 위치 확인 후 제자리로 복원 | 원본 이미지와 나란히 비교 |
| 16 | 자동 대조 스크립트(`audit_table_noise.py`, `verify_subjects.py`)의 구조적 오탐 | 이미 코드펜스/표로 잘 고쳐진 문항도 `<`, `-`(마지막 선택지), 7자리 학번 등 때문에 계속 히트로 잡힘; `verify_subjects.py`는 완전히 동일한 문구의 중복 문항이 두 과목에 걸쳐 있으면 id-num 매칭이 뒤바뀌어 **실제로는 정상인데 mismatch로 오보**하는 경우가 있음 (2024_1/2024_3 사례로 확인) | 히트 하나하나를 무조건 버그로 보지 말고, 이미 처리한 라운드에서 재등장하면 먼저 실제 PDF로 확인 후 "오탐"으로 분류 | 라이브 렌더링 + 원본 PDF 대조로 최종 판정 |

## 3. 작업 순서 (회차당, 1패스로 끝내기)
1. PDF → **이미지 렌더링(poppler) 우선**, 텍스트 추출은 보조용 (한글 인코딩 이슈 회피)
2. 60문항 전수를 [코드 / 그래프선택지 / 트리·그리드 / 박스형 / 특수표] 5개 카테고리로 1차 분류
3. 카테고리별로 2절 체크리스트 해당 항목 적용
4. **같은 화면 인접 문제까지 같이 처리했는지 재확인** (누락 방지, 규칙 3 관련)
5. "그림/표/다이어그램" 키워드 전수 재검색 → 필요/불필요 판정 (규칙 4)
6. 실전 모드 문제 순서(과목 우선 정렬) 확인
7. DB 재빌드
8. 라이브 화면 캡처로 원본과 1:1 대조 — **자동 스크립트만 믿지 않기**
9. 이상 없을 때만 "완료" 보고 → 커밋/푸시

## 4. 그대로 복사해서 쓰는 프롬프트
```
[회차명] PDF와 현재 DB 데이터를 아래 마스터 규칙에 따라 전수 대조해서
원본과 완전히 동일하게 만들어줘.
- 절대 규칙 1~6, 문제 유형별 체크리스트 1~11, 작업 순서 1~9를 그대로 따를 것
- 자동 대조 스크립트 결과만 믿지 말고, 라이브 화면 캡처로 직접 확인한 뒤에만 완료 보고
- 같은 화면에 여러 유형이 섞여 있으면 전부 같이 처리 (하나만 고치고 넘어가지 말 것)
- 완료 후, 이 문서에 없는 새로운 오류 유형을 발견했다면 12번 항목으로 추가 제안해줘
  (다음 회차부터 이 문서를 계속 업데이트해서 씀)
```

## 5. 대상 회차
2022_1, 2022_2, 2022_3, 2023_1, 2023_2, 2023_3, 2024_1, 2024_2, 2024_3, 2025_1, 2025_2, 2025_3, 2026_1 — **13개 회차 전부 완료** (마지막: 2025_3, 이 세션에서 완주)

각 회차마다 실제로 발견/수정한 항목은 git 커밋 로그(`git log -- data/cbt_questions.csv`)에 회차별로 남아있음. 요약:
- 대규모 정답 오류나 문제 자체가 틀린 사례는 발견되지 않음 — 발견된 것은 전부 **서식**(코드펜스/표/블록인용 누락) 또는 **순서**(qnum 미배정) 문제였음.
- 2022_1 라운드 작업 중 세션 도중 CSV 파일에서 12문항(id 1199~1210)이 통째로 잘려나간 사고를 발견·복구함 — 대량 CSV 재작성 스크립트를 돌린 뒤에는 항상 `git diff --stat`으로 행 수 변화를 확인할 것.

> 이 문서는 살아있는 문서(living doc)로 취급 — 새 회차 진행하다 새로운 오류 유형 나오면 2절에 계속 추가.
